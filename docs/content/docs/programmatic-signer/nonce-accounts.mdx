A Nonce program account stores a hash that advances each time an authorized action succeeds. It also records the authority allowed to advance it and the slot it was initialized in. An authority can hold as many nonce accounts as it needs. Each one advances independently of the others.

## Create a nonce account

Create the account and initialize it in the same transaction with the programmatic signer PDA as its authority. `Initialize` needs no signature, so an account left uninitialized could be claimed by someone else. It sets the first nonce from the most recent slot hash. The authority can never change after that.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

`nonce create` does both. `--cold-authority` takes the public key of your offline Ed25519 signer. The CLI derives its programmatic signer PDA and stores that PDA as the nonce authority.

```sh
spl-programmatic-signer nonce create --cold-authority <AUTHORITY>
```

Pass `--nonce-authority` instead of `--cold-authority` to store any address as given. The CLI generates a throwaway keypair for the new account unless you pass `--nonce-keypair`.

## Account layout

Fetch the account, check that the Nonce program owns it and that it holds exactly 72 bytes, then read the three fields.

| Byte range | Field               | Type      |
| ---------- | ------------------- | --------- |
| `0..32`    | Current nonce value | `Hash`    |
| `32..64`   | Authority           | `Address` |
| `64..72`   | Initialization slot | `u64`     |

## How the nonce advances

<NonceAdvanceDiagram />

Executor advances the nonce before running any application instruction, so nothing inside the message can consume the same nonce twice. `Advance` needs signer privilege from the nonce authority. When that authority is a programmatic signer PDA, Ed25519 Signer grants it after verifying the authority's signature. The Nonce program never interprets that hash. Executor is what ties it to the message it runs. [Execution source](https://github.com/solana-program/ed25519-programmatic-signer/blob/825ab23b00c9c014b4a0de96e4cb4e5e2e12def4/executor/program/src/execute.rs).

## Nonce derivation

Every nonce is a SHA-256 hash. Including the program ID and account address ties each one to a single nonce account. Each `+` below joins raw bytes. Addresses and hashes are their 32 bytes, not base58 text. The tags are plain UTF-8 with no terminator.

### First nonce

`Initialize` derives the first nonce from the most recent slot hash.

```text
first nonce = SHA-256("spl-nonce::init::v1" + Nonce program ID + nonce account + slot hash)
```

### Next nonce

Each `Advance` replaces the current nonce with a value derived from it.

```text
commitment = SHA-256(serialized execution message)
next nonce = SHA-256("spl-nonce::step::v1" + Nonce program ID + nonce account + current nonce
                     + transition signer + commitment)
```

The transition signer is a PDA the Message Executor derives at `EjCSGNbrrM7YJBwR9iqnrb87L1TYHfUtZ5L4gwQjWLFg`. The executor signs every `Advance` with it. This prevents the nonce authority from skipping an approved action and still reaching the nonce expected by the next authorization in the chain.

| Input             | Ties the next nonce to                                      |
| ----------------- | ----------------------------------------------------------- |
| Current nonce     | The step before it, so steps run in order                   |
| Transition signer | The executor that advanced it                               |
| Commitment        | The exact execution message that consumed the current nonce |

The Nonce program accepts any account that signs as the transition signer. A nonce authority that calls `Advance` directly with its own signer reaches a different next nonce. Any chain signed in advance then stops working.

These inputs are all known ahead of time, so anyone who knows the planned messages can compute future values. That gives ordering and replay protection. The values themselves are public and never meant to be secret. That is what makes [chains](#chain-actions-in-order) possible.

## Run actions in parallel

One authority can control any number of nonce accounts. Each advances independently, so authorizations on different accounts never block each other. Use a separate account for each independent stream of work.

Each authorization is bound to its own nonce account, so it cannot be relayed against a different one. Separate nonce accounts do not stop two actions from conflicting in other ways, such as two payments drawn from the same balance.

## Chain actions in order

A chain lets you sign several authorizations in one session and hand them to a relayer to run later, in a fixed order. For example, a treasury can sign next month's four weekly payouts at once on an air-gapped machine. The relayer can submit each one only after the previous one has run, so it cannot skip ahead, reorder them, or run one twice.

This works because each nonce depends on the one before it and on the exact execution message that consumed it, so every future value can be computed in advance. Build action A against the current nonce, compute the nonce A leaves behind, and build B against that.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

Build both execution messages as in [Basic usage](/docs/programmatic-signer/usage#build-the-execution-message). Save the base64 messages as `MESSAGE_A` and `MESSAGE_B`. `transaction sign` fills in each expected nonce.

```sh
spl-programmatic-signer transaction sign \
  --execution-message "$MESSAGE_A" \
  --strip-transaction-config \
  --nonce-account "$NONCE_ACCOUNT" \
  --nonce-hash "$NONCE_VALUE" \
  --nonce-authority "$PDA" \
  --authority "$AUTHORITY" \
  --signer authority.json
```

Keep A's authorization message and signature, and the next nonce value it leaves behind.

```sh
AUTHORIZATION_MESSAGE_A=<Authorization message from the output>
SIGNATURE_A=<Signature from the output>
NEXT_NONCE=<Next nonce value from the output>
```

Sign B against that next nonce. This works offline, since the value is computed. Keep B's authorization message and signature the same way.

```sh
spl-programmatic-signer transaction sign \
  --execution-message "$MESSAGE_B" \
  --strip-transaction-config \
  --nonce-account "$NONCE_ACCOUNT" \
  --nonce-hash "$NEXT_NONCE" \
  --nonce-authority "$PDA" \
  --authority "$AUTHORITY" \
  --signer authority.json
```

Submitting B before A fails, because the nonce account does not hold B's expected value yet.

```sh
spl-programmatic-signer transaction submit \
  --authorization-message "$AUTHORIZATION_MESSAGE_B" \
  --signer "$AUTHORITY=$SIGNATURE_B" \
  --fee-payer relayer.json
```

```text
Error: authorization message uses nonce value ETG5s3Cy6Gk3FN9zmaxC9KzU8h5trVHPBdkrq4WyEsBG, but nonce account DdUc3xdvrXGmc6bjSbpE1zgaqDA4TCEWCrqcSPz26CoD currently has 7nA2WQuAJAHsoMKx4L5NgqcpMzrTa7W3trdWif6yJWpb
```

Submit A the same way, then B. After both land, `nonce show` prints the next nonce value that signing B reported.

A chain runs strictly in order. If A fails, the nonce does not move, so A can be retried and B waits. The rest of the chain stops working if:

- A's execution message changes, since B expects the value A leaves behind
- another authorization or a cancellation consumes a value in the chain first

## Cancel an authorization

A signature cannot be recalled. To cancel an authorization that expects nonce `N`, get any other action that consumes `N` to land first. A keypair nonce authority can sign a plain `Advance` transaction. A programmatic signer PDA needs an approved execution message with no instructions, which advances the nonce and does nothing else.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

```sh
spl-programmatic-signer nonce advance "$NONCE_ACCOUNT" \
  --nonce-authority authority.json \
  --fee-payer relayer.json
```

```text
Signature: 427iF7zzJp3giypA2SUDujohxcRjWn9BxwTvK2ELEnhPdLptPKaYLV311Ld9T8DDLry13yBRpghJuNQ4ge8Tp858
Nonce account: DdUc3xdvrXGmc6bjSbpE1zgaqDA4TCEWCrqcSPz26CoD
Previous nonce: 3M6CDAu5tyaxAbtzetTMwPMbsKr3KPueE9CSAs1scBoJ
Nonce: DSwoLZkhbWt3SMoU4AZW42rHjbwPBWBKG3cbvp9wdo4h
```

`--nonce-authority` is the keypair that controls the nonce account. When the nonce authority is a programmatic signer PDA, as in this guide, pass the signing authority's keypair. This cancels every authorization built against the previous value and every chained step after it.

If the signing authority can't run the CLI, pass its address instead. `nonce advance` then prints an unsigned authorization message to sign externally and submit like any [external signature](/docs/programmatic-signer/signing#sign-with-an-external-signer). `nonce withdraw` works the same way.

The cancellation and the original authorization compete for the same nonce. Whichever lands first consumes the nonce, so the other fails.

## Failure and retry

A failed relay transaction rolls back the nonce advance, so the authorization stays valid. Submit it again or cancel it with `nonce advance`. Retrying after a timeout is safe, since an authorization that already landed fails on resubmission.

## Deadlines

Authorizations have no built-in deadline. They stay valid until their nonce account advances.

To add a deadline, include an instruction in the execution message that fails after it, such as [Lighthouse](https://github.com/Jac0xb/lighthouse)'s `AssertSysvarClock`. After the deadline the action fails and the nonce does not move.

## Withdraw and close

`Withdraw` sends lamports from the nonce account to another account. A partial withdrawal must leave the rent-exempt minimum. Withdrawing the full balance closes the account, which is allowed only after its initialization slot so no one can recreate it to restore its first nonce.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

Pass `ALL` to withdraw the full balance and close the account.

```sh
spl-programmatic-signer nonce withdraw "$NONCE_ACCOUNT" "$RECIPIENT" ALL \
  --nonce-authority authority.json \
  --fee-payer relayer.json
```

```text
Signature: 3xKK8acQ33Sfe2KYJ2BhwgEdKbfidhDCcorPUtWaMWsR7oM8rrZSXMQRzE9EP7yjXG5KB3cVwDUALBxP4Htnki73
Nonce account: EDGer1HU5yWvPRBUQx4wq68gEsH4dscsXsgh1vdf5qxb
Destination: BjvtG87DbdELr62KjDtvUVvt7SLKTXRy92BGfJrnfzph
Withdrawn: ◎0.001016000
Nonce account closed
```

To withdraw part of the balance, pass an amount instead of `ALL`.
