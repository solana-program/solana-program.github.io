## Fund a fee payer

The fee payer signs and pays for every transaction you send, including the relay. It also funds the nonce account and the PDA below, so about 0.02 Devnet SOL is enough. Fund it from the [Solana Faucet](https://faucet.solana.com/).

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

Create a relayer key and print its address for the faucet.

```sh
solana-keygen new --no-bip39-passphrase --outfile relayer.json
solana-keygen pubkey relayer.json
```

## Derive the programmatic signer

The authority is an Ed25519 keypair. Its programmatic signer is a PDA derived from the authority's public key and has no private key of its own. Once the Ed25519 Signer program verifies the authority's signature, the PDA acts as a signer for the approved instructions.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

```sh
solana-keygen new --no-bip39-passphrase --outfile authority.json
AUTHORITY=$(solana-keygen pubkey authority.json)
PDA=$(spl-programmatic-signer address "$AUTHORITY")
```

Fund the PDA. The example action on this page transfers 0.001 SOL from it using Programmatic Signer.

```sh
solana transfer "$PDA" 0.01 \
  --from relayer.json \
  --fee-payer relayer.json \
  --allow-unfunded-recipient
```

Deriving the address gives the PDA no control over anything yet. For SOL, fund it. For tokens, stake, or a program, make the PDA the authority first. See [migration](/docs/programmatic-signer/migration).

## Create a nonce account

Create the account and initialize it in the same transaction with the PDA as its authority. This account provides replay protection. Each authorization expects the account's current nonce value. Executor advances that value when the action runs, so the same authorization can never execute twice.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

```sh
spl-programmatic-signer nonce create \
  --cold-authority "$AUTHORITY" \
  --fee-payer relayer.json
```

`--cold-authority` takes the public key of your offline Ed25519 signer. The CLI derives its programmatic signer PDA and stores that PDA as the nonce authority. `--nonce-authority` stores an address as given instead. The CLI generates a throwaway keypair for the new account unless you pass `--nonce-keypair`, fetches the rent minimum, sends `CreateAccount` and `Initialize` together, and reads the account back. The output includes the nonce account address and its first nonce value. Keep the address.

```sh
NONCE_ACCOUNT=<Nonce account from the output>
```

## Read the nonce

Read the current value right before building an authorization. The signing machine is often air-gapped and cannot check it, so the value goes into the message on the online side.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

```sh
spl-programmatic-signer nonce show "$NONCE_ACCOUNT"
```

The CLI checks that the account exists, belongs to the Nonce program, and is initialized. Then it prints the account details.

```sh
NONCE_VALUE=<Nonce from the output>
```

## Build the execution message

The execution message is a v1 message with the instructions to run. This page builds a SOL transfer as an example, but yours can hold any instructions your application needs. It lists the PDA as a required signer and carries the current nonce in its blockhash field. In this example, the PDA is also the nonce authority. A different PDA can be the nonce authority if its own authority also signs the authorization.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

The Solana CLI can compile a message without sending it. Pass the nonce value as the blockhash and the PDA as both the source and the fee payer.

```sh
solana transfer <RECIPIENT> 0.001 \
  --from "$PDA" \
  --fee-payer "$PDA" \
  --blockhash "$NONCE_VALUE" \
  --sign-only \
  --dump-transaction-message \
  --allow-unfunded-recipient
```

Keep the base64 value printed as `Transaction Message`:

```sh
EXECUTION_MESSAGE=<Execution message from the output>
```

## Simulate the action

`transaction simulate` runs the execution message through `Submit` and the Message Executor. It needs no signatures, so you can check the action before anyone signs.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

```sh
spl-programmatic-signer transaction simulate "$EXECUTION_MESSAGE" "$NONCE_ACCOUNT" \
  --strip-transaction-config \
  --fee-payer relayer.json
```

## Review and sign

The authorization message is what the authorities sign. It names the executor program that will run your execution message and the nonce account used for replay protection. Your signature covers all of it, including every byte of the execution message.

You can review and sign entirely offline.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

`transaction sign` builds the authorization message from the execution message and signs it. It makes no RPC calls.

```sh
spl-programmatic-signer transaction sign \
  --execution-message "$EXECUTION_MESSAGE" \
  --strip-transaction-config \
  --nonce-account "$NONCE_ACCOUNT" \
  --nonce-hash "$NONCE_VALUE" \
  --nonce-authority "$PDA" \
  --authority "$AUTHORITY" \
  --signer authority.json
```

| Flag                | Meaning                                                                                                                                  |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `--execution-message` | The base64 v1 execution message                                                                                                             |
| `--nonce-account`   | The Nonce program account that protects the action                                                                                       |
| `--nonce-hash`      | The expected nonce value. Replaces the execution message's blockhash field                                                               |
| `--nonce-authority` | The address stored in that nonce account, normally the PDA                                                                               |
| `--authority`       | Repeat for every key whose PDA needs signer privilege                                                                                    |
| `--signer`          | Which key signs: a keypair file, `usb://ledger`, `prompt://`, or `ASK`. Repeat for several local keys. Each must appear in `--authority`. |
| `--strip-transaction-config` | Clear compute budget and other config fields from the execution message instead of rejecting it |

## Relay

The relayer sends the authorization in a relay transaction. It puts the authorization message and signatures into a `Submit` instruction, adds a fresh blockhash, and signs as the fee payer. The authority does not sign the relay transaction, so it can stay offline.

<Tabs groupId="programmatic-signer-client" items={["CLI", "TypeScript"]} persist defaultIndex={0}>
<Tab value="CLI">

```sh
AUTHORIZATION_MESSAGE=<Authorization message from the output>
SIGNATURE=<Signature from the output>
```

Check the complete relay transaction first. `--dry-run` simulates it with the real signature and reports its fee, but signs and sends nothing.

```sh
spl-programmatic-signer transaction submit \
  --authorization-message "$AUTHORIZATION_MESSAGE" \
  --signer "$AUTHORITY=$SIGNATURE" \
  --fee-payer relayer.json \
  --dry-run
```

```text
Simulation succeeded (54379 compute units)
Fee: ◎0.000005000

SOL balance changes:
  ottvxCwqvBwNuMkBgmqz2HU16BhyfpZVwAxvWrzxGg6  -◎0.000005000
  4eyTy3ArvmhdNHyNHHynNmfoxuoyjP5oeb9xWpdn8vAz  -◎0.001000000  (PDA of DRE2gQ6RxNZtt175DB1H4ABCiFtnTY9NERGVW2VAAZwg)
  5w9aEhwnNex4TNXvD9nsEtdE6i7pSWukJEXjbZXWuHuz  +◎0.001000000

Token balance changes:
  none
```

Then submit. The CLI checks that the nonce account still holds the expected value, signs with the fee payer, and prints the relay transaction signature.

```sh
spl-programmatic-signer transaction submit \
  --authorization-message "$AUTHORIZATION_MESSAGE" \
  --signer "$AUTHORITY=$SIGNATURE" \
  --fee-payer relayer.json
```

## Check the result

```sh
solana balance "$RECIPIENT"
solana balance "$PDA"
spl-programmatic-signer nonce show "$NONCE_ACCOUNT"
```

The recipient holds 0.001 SOL, the PDA holds 0.009 SOL, and the nonce account now holds the next nonce value printed when signing. Submitting the same authorization again fails because the nonce it expects is gone.

```text
Error: authorization message uses nonce value C3QNdWqr8N6RLrQkiqi6gntS1T1tAhNckSAUAkhdHr5X, but nonce account C2kRQSqLD2m1UHBr8xwKs7SPuyLJVo4GcGbjiKrDd3gT currently has 5RDZbe7pzEjFfJZtAbNFBY9vU4pX7oDeJmfxvjaEW9aT
```

If a relay transaction fails, the whole action rolls back, including the nonce advance. The authorization can still be submitted later.
